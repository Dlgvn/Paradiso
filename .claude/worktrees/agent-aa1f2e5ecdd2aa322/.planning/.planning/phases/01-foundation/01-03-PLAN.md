  <action>
1. Ensure `next.config.ts` has `images.remotePatterns` configured for poster images that will come from OMDB/Open Library in later phases. Add patterns for:
   - `m.media-amazon.com` (OMDB poster source)
   - `covers.openlibrary.org` (Open Library cover source)
   - `image.tmdb.org` (fallback if TMDB is ever used)
   This prevents next/image errors when poster backdrops are added in Phase 3.

2. Deploy to Vercel using the CLI:
   ```bash
   cd media-tracker-v3
   npx vercel --yes
   ```
   If the `vercel` CLI is not installed, install it first: `npm install -g vercel`
   Follow the prompts — link to a new Vercel project, accept defaults for framework (Next.js) and build settings.

3. Set environment variables on Vercel:
   ```bash
   npx vercel env add NEXT_PUBLIC_SUPABASE_URL production
   npx vercel env add NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY production
   ```
   The user will need to provide actual Supabase project values here. If `.env.local` still has placeholder values, STOP and prompt the user to update them first.

4. Trigger a production deployment:
   ```bash
   npx vercel --prod
   ```

5. Record the production URL in the plan summary.

6. Configure git integration for auto-deploy on push:
   ```bash
   npx vercel git connect
   ```
   This links the GitHub/Git repo so pushes to main trigger automatic deployments.

NOTE: If the user has not set up real Supabase credentials yet, the deployment will still work — the app renders fine without a live Supabase connection (it just shows a connection error on the movies page, which is expected). The critical thing is the design system rendering correctly.
