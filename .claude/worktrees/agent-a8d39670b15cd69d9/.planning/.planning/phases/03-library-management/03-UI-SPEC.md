## Interaction Contracts

### Card Hover Overlay (Library Cards)

- Trigger (desktop): `mouseenter` on card
- Trigger (mobile): tap anywhere on card
- Overlay appears: dark frosted panel slides up from bottom of card. Duration: 180ms ease-out.
- Overlay contains: title (14px/400), year (12px/400), star rating row (read-only, gold stars), favorite heart button (20px icon), status badge (tappable)
- Status badge tap: opens Radix `DropdownMenu` anchored to badge. Options: Watchlist / Watching / Completed / Dropped. Selection fires `updateItemStatus` Server Action with `useOptimistic` for instant UI update.
- Favorite heart tap: fires `toggleFavorite` Server Action with `useOptimistic`. Heart fills/empties immediately.
- Overlay dismisses: `mouseleave` (desktop, with 80ms debounce to prevent flicker when moving to dropdown), tap outside (mobile)
- Pitfall guard: Use Radix `DropdownMenu` — not CSS-only hover — so cursor movement into the dropdown does not dismiss the overlay (see RESEARCH.md Pitfall 6)

### Add Item Flow (Search Page)

1. User types in search input → debounce 350ms → fires Server Action → results appear as poster grid (or skeleton while loading)
2. User taps a search result card:
   - If not in library: `AddItemDialog` opens immediately
   - If already in library: `DuplicateWarningDialog` opens first ("Already in your library as [Status]. Add anyway?")
     - "Add Anyway" → `AddItemDialog` opens
     - "Keep Existing" → dialog closes, no action
3. `AddItemDialog`: user selects status (required, defaults to "Watchlist"), optionally sets rating (1–10, skip button available)
4. User taps "Add to Library": fires `addMediaItem` Server Action
   - On success: dialog closes, result card shows "Added" badge (accent background, white text, 12px). Badge fades in: 120ms opacity transition.
   - On error: error message appears inside dialog. Dialog stays open.
5. User can continue searching and adding without navigating away (stays on /search)

### View Toggle (Library Pages)

- Grid button active: LibraryGrid renders CSS Grid (2/4/6 columns by breakpoint)
- List button active: LibraryGrid renders flex column of MediaListItem rows
- State stored in URL param `?view=grid|list`. Default: `grid`.
- Toggle is instant (no animation needed — layout shift is clear enough)

### Status Filter Tabs (Library Pages)

- Tab click: updates URL param `?status=watchlist|watching|completed|dropped`
- Active tab: 2px accent underline, text at full opacity
- Inactive tab: text at 60% opacity, no underline
- Default: Watchlist tab selected on page load
- If filtered view is empty: `EmptyState` component renders with context-aware copy (see Copywriting Contract)

## Loading and Error States

### Search Loading
- State: API fetch in-flight after user types
- UI: Skeleton grid — 8 pulse-animated poster-shaped cards (same dimensions as SearchResultCard). Backdrop-filter: blur(4px) on skeleton items.

### Search Error
- State: OMDB or Open Library API returned an error
- UI: Inline error message below the search input. Copy: "Couldn't reach [Movies / Books] search. Check your connection and try again." Accent-colored "Try Again" button retries the last query.
- No full-page error state — search input remains usable.

### Add Action Error
- State: `addMediaItem` Server Action returns error
- UI: Error text appears inside `AddItemDialog` below the rating selector. Copy: "Something went wrong adding [Title]. Try again." Dialog stays open. Retry by tapping "Add to Library" again.

### Favorite / Status Update Error
- State: `toggleFavorite` or `updateItemStatus` Server Action returns error after optimistic update
- UI: Optimistic update rolls back silently. Toast notification appears (bottom-center): "Couldn't save change. Try again." Duration: 4 seconds.
