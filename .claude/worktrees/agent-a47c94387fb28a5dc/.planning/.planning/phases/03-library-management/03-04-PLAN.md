**File 1: `src/app/(app)/search/page.tsx`**

This is the main search page. Structure:

Top-level: Two tabs — "Add New" (active in Phase 3) and "My Library" (placeholder). Use shadcn `Tabs` component.

"Add New" tab content (client component or mixed):
1. Search input: text field with placeholder "Search movies, series, or books...", debounce 350ms before firing search
2. MediaTypeSelector below input: Movies / Books / Series toggle
3. Results area:
   - While loading: SearchSkeleton
   - On results: Poster grid of SearchResultCard components (same grid as library: 2/4/6 cols)
   - On no results: Inline message "No results for [query]" with "Try a different title or switch to another media type." body text
   - On error: Inline error below search input with "Try Again" accent button

**Search logic** (client-side state management):
- State: query (string), mediaType ('movie'|'book'|'series'), results (array), isLoading (boolean), error (string|null), existingItems (Map<externalId, status>)
- On query change (after 350ms debounce): call appropriate Server Action based on mediaType
  - movie: `searchMovies(query)`
  - series: `searchSeries(query)`
  - book: `searchBooks(query)`
- After results arrive, do a batch duplicate check: extract all external IDs from results, call `checkDuplicate` for each (or better: create a batch check — but since checkDuplicate takes one ID, map over results in parallel with Promise.all)
- Pass existingItems map to each SearchResultCard

**Search input:** Use a `useEffect` + `setTimeout` debounce pattern (or `useDeferredValue`). Clear results when mediaType changes.

"My Library" tab: renders MyLibraryPlaceholder component.
